# H5P Core 1.28 contract checks

These tests use the vendored classes and Backdrop adapter without loading the
Backdrop bootstrap, settings, database connection or HTTP endpoints. Config,
platform-information queries, stream wrappers and hooks have in-memory doubles.
Every other database query throws. Hub HTTP is mocked. ZIP extraction, storage
copies and cleanup are confined to a randomly named, owned OS temporary tree.
Existing exports are opened read-only and copied before validation; original
hashes are compared before and after each test. Nothing is installed or saved
to the site's content/library directories.

## Run on the existing WAMP runtimes

From `C:/wamp64/www/backdrop/modules/h5p`, in PowerShell:

```powershell
& 'C:/wamp64/bin/php/php7.4.33/php.exe' -n `
  -d extension_dir=C:/wamp64/bin/php/php7.4.33/ext `
  -d extension=mbstring tests/core-api-128.php

& 'C:/wamp64/bin/php/php8.4.22/php.exe' -n `
  -d extension_dir=C:/wamp64/bin/php/php8.4.22/ext `
  -d extension=mbstring -d extension=zip tests/core-api-128.php

& 'C:/nvm4w/nodejs/node.exe' tests/core-jquery-compatibility.cjs
```

PHP 7.4's ZIP extension is built in on this installation; requesting its missing
ZIP DLL produces an unnecessary startup warning. PHP 8.4 requires the ZIP DLL.
Tests convert unmasked PHP warnings/deprecations into failures. No Composer,
npm, PHPUnit or browser dependencies are installed. Native ZIP renames needed
sandbox escalation in this Codex session; normal local runs use the OS temp path.

## Real export fixtures

Append `--fixtures=C:/wamp64/www/backdrop/files/h5p/exports` to either PHP command
to validate all 21 current packages AND check their frozen Phase 1 hashes.
Three exports were regenerated by the working site during Phase 2, as confirmed

Append `--skip-fixture-baseline` as well when explicitly testing those current,
regenerated exports. The test prints the skipped historical check; it still
checks every original file's hash before/after validation and never rewrites
the baseline. The observed changes are recorded in
`docs/h5p-api-1.28/fixture-observations.json`.

`--baseline` is for running the contract on the original API 1.24 source snapshot
in a separate checkout. Do not expect it to pass against the upgraded vendor
tree. No baseline checkout or site/database clone is created by these tests.

## Scope and limits

The tests exercise actual package validation, complete PHP interfaces, folder
helpers, dependency URLs, the old editor's presave call, Backdrop's core factory,
alternate editor storage, copied media, hooks, option defaults, saved allowlists,
Hub credential reset, group values, source provenance and runtime resource paths.
They check retained editor vendor hashes against Phase 1, and reverse only the exact registered Step 2 adapter spans before platform comparisons.
The Node test exercises the actual H5P wrapper with jQuery/window doubles, not a
browser DOM or the complete jQuery engine. It explicitly characterizes the pinned
upstream `.load(url)` defect; `.load(fn)` is covered as a working contract.

These checks do not establish browser playback/editor compatibility, HTML
round trips, real database revision behavior, all semantics filtering, live Hub
registration, permissions or HTTP asset delivery. Qualify those in an isolated
Backdrop installation with its own database/files before accepting the upgrade.

## Targeted node-cache regression

Run `tests/node-cache.php --backdrop-root=C:/wamp64/www/backdrop-h5p-test`
on PHP 7.4 and 8.4. The suite reads Backdrop's real entity controller without
bootstrapping a site. SQL records, node queries and persistent caches use memory
fixtures. Actual H5P node loading and Core filtering reproduce the previous
stale-cache behavior, then verify one-time filtering followed by warm playback
and edit loads in the same and subsequent requests. Existing exports are reused.
Revision and non-revision IDs resolve to the owning node; unrelated nodes retain
their static identity and persistent bytes. Missing owners and failed writes
never trigger a broad flush. Raw parameters and metadata remain unchanged.

The adapter calls `entity_get_controller('node')->resetCache(array($nid))`
after successful field persistence. It does not reload a node, save content,
rebuild libraries or clear any other cache bin. Exact patch bytes are registered
in `docs/h5p-api-1.28/node-cache-patches.json`; prior provenance checks remain
active after reversing only this patch.
